没有NAS不要愁！Windows使用WSL安装docker容器体验服务器功能

发表于： 2026-08-26 分类于： NAS
字数： 3443 阅读：≈ 7分钟 浏览：

摘要

本文介绍了在 Windows 11 上安装并配置 WSL 的全过程。首先检查虚拟化并安装 Debian 系统。针对 WSL 命令繁琐的问题，推荐使用 WSL Dashboard 进行可视化管理。随后详细配置了系统环境，包括安装 Docker、国内源、SSH 服务及面板（如 KPanel），并调整网络模式。最后通过防火墙设置实现局域网访问，适合无 NAS/VPS 用户搭建本地服务器。

前言

前两天试用了一下微软新发布的 WSLC 跑 docker 容器，解决了内存占用的问题。但是这个应用还处在初级阶段，比如只能装在 Windows 11 上，不支持可视化面板，不支持 docker compose，对于我来说还不太可用，所以装回了原版WSL。WSL 本质是 Hyper-V 虚拟机，所以可以跑完整的 Linux 系统，功能没有阉割。

前置条件

  1. 检查是否开启了虚拟化，任务管理器中，虚拟化应该显示已开启，否则去 BIOS 中查看对应设置进行开启
  2. 网络，我看到很多人有这个问题，但只能自己想办法解决了

安装

  1. 安装 WSL 和对应的 Linux 虚拟机，以 Debian 为例

纯文本

1

wsl --install -d Debian --name debian --location c:/wsl/debian

运行命令后会先安装 WSL，中途会要求输入新建用户名和密码，完成后就进入 docker 内

  1. 退出虚拟机 exit

  2. 查看当前虚拟机 wsl -l

  3. 查看能够安装的 linux 系统 wsl -l -o，也可以装 Ubuntu 等其他系统

  4. 如果想要启动后直接进入用户目录，直接输入 wsl ~

  5. 关闭虚拟机 wsl --shutdown

  6. 设置虚拟机，打开 wsl settings， 设置 CPU 数量，内存，硬盘大小，

  7. 重点网络模式，修改成镜像 mirrored，同时勾选主机地址环回，这样就能用本机地址来访问 docker 容器了。

  8. 删除虚拟机 wsl –unregister U 3

  9. 删除 WSL wsl –uninstall

可视化

WSL 需要记很多命令，尤其是多个系统的情况下，管理起来有点麻烦，备份、自启动等功能都需要复杂指令，不想记的话可以安装这个开源项目 WSL Dashboard 项目地址：https://github.com/owu/wsl-dashboard/

可以一键安装、列出、启动、停止、取消注册，并从一个地方配置你的 WSL 发行版。

使用

WSL 本质是虚拟机下的 Linux 系统，所以按照服务器的配置方法设置就可以了，列举一些必备设置，也可以参考我之前安装本地服务器的文章。

结尾

此时服务器就基本设置完成，功能齐全，安装 WSL Dashboard 后也非常轻松的解决了开机自启，目录访问等很麻烦的操作，也可以通过内网穿透在公网访问本地应用，非常适合没有 NAS 或 VPS 的小伙伴学习体验。

别再开虚拟机了！微软原生 WSLC 容器，才是 Windows 跑容器的终极答案！

摘要

微软全新原生方案 WSL Container（wslc），一条命令替代 Docker，免费开源、无守护进程、支持 GPU 直通。本文手把手带你安装、上手核心命令，并对比 Docker Desktop 与 Podman。

前言

之前如果需要在 Windows 上跑 docker 容器的话，一般会选择 Docker Desktop，优点是操作方便、兼容性强，但是问题也很多，比如我的笔记本跑起来就很吃内存，启动也慢。 微软刚刚发布了全新的原生方案——WSL Container（wslc），一条命令替代 Docker，零成本平替，免费开源，无守护进程，还有 GPU 直通，好用多了。

安装实操

前置条件

  • CPU 开启硬件虚拟化（BIOS 里开 Intel VT-x 或 AMD-V）
  • Windows 10 2004+ 或 Windows 11
  • 已启用「适用于 Linux 的 Windows 子系统」和「虚拟机平台」
  • WSL 版本 ≥ 2.9.3（wslc 最低支持基线）

Step 1：更新 WSL 到预览版

稳定版 WSL 不含 wslc，必须拉取预发布版本。打开管理员权限的 PowerShell：

纯文本

1

wsl --update --pre-release

看到类似「正在更新适用于 Linux 的 Windows 子系统: 2.9.4」就说明成功了。

Step 2：关闭所有 WSL 实例

纯文本

1

wsl --shutdown

彻底释放正在运行的 WSL 内核进程，保证新版本内核完整加载。

Step 3：重新开一个新终端

这是最容易踩坑的一步！更新后旧终端无法识别 wslc 命令，因为旧终端进程启动时加载的 PATH 缓存里还没有 wslc.exe。必须关掉所有已打开的 PowerShell / Windows Terminal 窗口，重新新开一个管理员终端。

仅执行 wsl --shutdown 是不够的——它只关闭 Linux 内核，不会刷新 Windows 终端的可执行文件缓存。

Step 4：校验 WSL 版本

纯文本

1

wsl --version

确认输出中 WSL 版本 ≥ 2.9.3：

纯文本

1
2
3

WSL 版本: 2.9.4.0
内核版本: 6.18.35.2-1
WSLg 版本: 1.0.79

Step 5：校验 wslc

纯文本

1

wslc version

正常返回 wslc 2.9.4.0 就说明安装成功了！

3 个不踩坑实操建议

建议 1：安装后必须重启终端

最高频踩坑点。执行 wsl --update --pre-release 后，旧终端进程的 PATH 缓存里还没有 wslc.exe。 正确流程：更新 → shutdown → 关闭所有终端 → 重新新开管理员终端 → 验证版本。 如果新开终端还不行，用 Test-Path C:\Windows\System32\wslc.exe 检查二进制文件是否存在，不存在就重新更新。终极兜底：重启电脑。

建议 2：多工具共存，不冲突

Windows 上可以同时保留传统 WSL 发行版（Ubuntu、Debian 等）、Podman machine、wslc 三套环境。三者内核运行层隔离，互不抢占资源。日常开发用 wslc 跑轻量容器，需要 Docker Compose 或 K 8 s 时切回 Docker Desktop 或 Podman，按需切换即可。

建议 3：了解当前限制，别盲目替换

WSLC 目前处于公开预览阶段，以下功能暂不支持： ❌ Docker Compose（多容器编排） ❌ 自定义复杂网桥网络 ❌ 持久卷高级挂载 ❌ 可视化管理面板（纯 CLI） ❌ K8s 集群

如果你的工作流强依赖 docker-compose.yml，现阶段不建议完全卸载 Docker Desktop。把 wslc 当作轻量替代 + 补充工具使用更稳妥。

总结

WSLC 是什么：微软把容器运行时直接做进了 WSL 2 内核，无需 Docker Desktop 即可在 Windows 上构建、运行、管理 Linux 容器。

核心优势：免费、零额外安装、命令兼容 Docker、GPU 直通、资源占用低、文件 IO 性能翻倍。

适合谁：本地轻量开发、临时数据库/中间件容器、AI 推理环境、不想装重型容器客户端的用户。

不适合谁：需要 Docker Compose、K8s、可视化面板、企业集群管理的生产环境。

最佳实践：wslc + Docker Desktop 双工具共存，轻量任务用 wslc，复杂编排用 Docker，按需切换。
